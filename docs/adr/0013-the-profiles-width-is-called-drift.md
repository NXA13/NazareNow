# The Forecast Error Profile's width is called drift

`CONTEXT.md` defines a Forecast Error Profile as how far third-party forecasts **drift**, and
puts "noise" on the entry's _Avoid_ list. The shipped schema said `noise`, and `distribution.py`
renamed it on the way in:

```python
drift, bias = band.noise, band.bias
```

One quantity wearing two names across a file boundary, with nothing checking they mean the same
thing. That is the hazard, not the wording — and `drift` is not a coined word. It is the one the
domain already had, in the glossary's own definition and in `_drift_floor` / `_unmeasured_drift`
since #15.

**The width is `drift` everywhere**: `forecast_error.json`'s band key, `Band.drift`, the `drift`
column of `drift_by_lead_time.csv` and `total_error_by_lead_time.csv`, `Summary.drift` in the
writer, and `wind_sensitivity.py`'s `wind_speed_drift_kmh` / `wind_direction_drift_deg`.

## `bias` stays, and that is a decision

It is the exact statistical term for the signed component, and the glossary sanctions no
replacement for it. Coining one would add a third vocabulary rather than remove a second, and a
made-up word is worse than a borrowed one when the borrowed one is standard everywhere the
measurement is discussed. In prose, "the signed part of the drift" says the same thing without
borrowing a word that also means prejudice — which is what the _Avoid_ list is for.

## What this does not decide

**Only the Forecast Error Profile entry.** Whether the other _Avoid_ lists in `CONTEXT.md` bind
identifiers as well as prose is left open, deliberately, because deciding it here would rule on
code this change never looked at. Two cases are already reachable and are *not* settled by this
ADR:

- Model Spread avoids "confidence", and `analysis/forecast_error/confidence.py` is named for it.
- Predictive Distribution avoids "prediction", and `decision.py` carries `Prediction` and
  `prediction` throughout.

Both may be fine, or may be the same defect. Neither was measured, so neither is ruled on.

## An old profile now fails to load, on purpose

`NAZARENOW_FORECAST_ERROR` exists so the profile can be re-measured without a redeploy, so a
deployment really can be pointed at a file written before this change. Such a file now raises
`ForecastErrorUnusable: … is missing 'drift'`.

Accepting either key would be the tempting kindness and the wrong one: it would make the two
spellings mean one thing again, which is exactly the ambiguity being removed, and it would do so
permanently rather than for a migration window nobody would ever close. A width is also the one
field whose wrongness does not look wrong to a reader — too narrow reads as confidence — which is
why `ForecastErrorUnusable` refuses rather than defaults everywhere else in that module.

## The one hand-edit, and why it is not a #39 violation

#39's rule is that generated artifacts are regenerated, never hand-typed, so that no measured
value can be introduced by a keystroke. `forecast_error.json` was regenerated by
`analysis/forecast_error/profile.py` accordingly, and all 70 band fields are identical after the
key rename.

`amplification.json` could not be: `train.py` needs sklearn and scipy, neither installed, and
running it would **refit the model**. Changing fitted coefficients to repair a cross-reference is
a far worse trade than the one #39 was written to prevent. Its `is_a_width` field named "the
Forecast Error Profile's noise", which this rename falsifies, so `train.py`'s string literal and
that one sentence in the generated file were changed together by literal text replacement. The
diff is a single line and all 29 numeric fields were verified identical to the previous commit.

Because the generator's literal moved with it, the next refit reproduces the committed string
rather than reverting it. The alternative — leaving the cross-reference false — is precisely the
defect class ADR 0012 was adopted to prevent, one commit earlier.

## Consequences

- The glossary and the shipped schema agree. Before this they contradicted each other and a
  reader had no way to know which was authoritative, which is what #65 was filed about.
- A pre-#65 profile file is refused at load with its cause named.
- No measured value changes anywhere: the wave-run profile, the amplification parameters and the
  wind-perturbation table all report exactly what they reported before.
